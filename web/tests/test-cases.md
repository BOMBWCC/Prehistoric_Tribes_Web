# 史前部落网页版：Playwright 测试用例（代替人工测试）

给执行测试的 AI 或测试人员看。读完这一份就能开工，不需要看别的文档。
目标：代替真人在手机上玩，查出**规则错误、数值错误、状态错乱、画面和动作问题**。

版本：2026-11-06。游戏规则以这份文档为准；如果游戏和这里不一样，先按“规则不符”报告，不要改游戏代码。

## 1. 准备环境

```bash
git clone https://github.com/BOMBWCC/Prehistoric_Tribes_Web.git
cd Prehistoric_Tribes_Web/web
npm install
npx playwright install chromium   # 没装 Google Chrome 时需要
npm run dev                        # http://localhost:5173，端口固定
npm test                           # 345 个函数测试
npm run scenarios                  # 113 个已有场景测试（用本机 Google Chrome）
```

先跑后两条。**它们有失败的话，先报告，再继续。** 本文的用例是在它们之外，补上人工测试才能发现的问题。

**必须测本地开发服务器，不能测线上网址。** 下面用到的调试接口只在 `localhost` / `127.0.0.1` 上打开。线上地址 <https://bombwcc.github.io/Prehistoric_Tribes_Web/> 只用于 M 组的加载测试。

## 2. 两种测试模式

| | 调试模式（测规则、数值） | 真实模式（测画面、动作、手感） |
|---|---|---|
| 进入方式 | `__prehistoricDebugBootWithoutSplash()`，再 `S.enter(关卡)` | 从开始菜单点进去 |
| 时间 | 主循环停着，`S.step(n)` 才走 n 步；很快，可重复 | 真实时间，每步 120 毫秒（约每秒 8 步） |
| 随机数 | 种子固定，结果可重现 | 点击时机不同，结果会有差异 |
| 用来测 | 大部分状态和数值用例 | 标 **[真实]** 的用例，所有动作和流畅度用例 |

**游戏时间换算**：1 步 = 120 毫秒；500 步 = 1 游戏分钟 = 成年人 1 岁 = 真实 60 秒。

### 2.1 起步代码

放在 `web/tests/` 下运行，开发服务器要先开着。

```js
// web/tests/my-tests.mjs
import { chromium } from "playwright";
import path from "node:path";

const BASE = process.env.BASE ?? "http://localhost:5173/";
const web = path.resolve(path.dirname(new URL(import.meta.url).pathname), "..");
const root = path.resolve(web, "..");
export const browser = await chromium.launch({ headless: true }); // 有 Chrome 时可加 channel: "chrome"

export async function open({ real = false, map = 11 } = {}) {
  const context = await browser.newContext({ viewport: { width: 390, height: 844 }, deviceScaleFactor: 2, isMobile: true, hasTouch: true });
  const page = await context.newPage();
  const errors = [];
  page.on("pageerror", (e) => errors.push(e.stack ?? e.message));
  page.on("console", (m) => { if (m.type() === "error") errors.push(m.text()); });
  await page.addInitScript(() => { try { localStorage.clear(); } catch {} });
  await page.goto(BASE);
  // 本地才有的调试文字盖在画面上半部分：一定要藏起来，否则截图和点击都不对。
  await page.addStyleTag({ content: 'pre[aria-label="Legacy runtime debug overlay"]{display:none!important}' });
  if (real) {
    await page.waitForFunction(() => document.querySelector(".start-menu")?.dataset.page === "main", null, { timeout: 120000 });
    await page.tap('.start-menu button[aria-label="custom"]');
    await page.waitForTimeout(150);
    await page.tap('.start-menu button[aria-label="easy"]');
    await page.waitForTimeout(150);
    await page.tap(`.start-menu .start-map >> nth=${map - 7}`);
    await page.waitForFunction(() => window.__prehistoricRuntime?.game.loopMode === 1, null, { timeout: 60000 });
  } else {
    await page.waitForFunction(() => !!window.__prehistoricDebugBootWithoutSplash);
    await page.evaluate(() => window.__prehistoricDebugBootWithoutSplash());
  }
  await page.addScriptTag({ path: path.join(root, "tools/debug/stage.js") }); // window.S：摆局面
  await page.addScriptTag({ path: path.join(web, "tests/inspect.js") });      // window.T：读状态
  if (!real) await page.evaluate((map) => { S.enter(map); S.step(3); }, map);
  return { page, context, errors };
}

/** 地图格 (x,y) 的屏幕坐标，先把镜头移过去。调试模式下，调用后要 S.step(20) 让镜头到位，再调一次取坐标。 */
export async function tile(page, x, y) {
  return page.evaluate(([x, y]) => {
    S.look(x, y); __prehistoricRuntime.game.cameraBFlag = false;
    const s = __prehistoricScreen, b = s.element.getBoundingClientRect(), p = s.tileToCss(x, y);
    const k = s.tileToCss(1, 1).x - s.tileToCss(0, 0).x;
    return { x: b.left + p.x + k / 2, y: b.top + p.y + k / 3 };
  }, [x, y]);
}

/** 真实手指拖动：拖地图、拖建筑、滑列表、拖武器都用它。 */
export async function swipe(page, x0, y0, x1, y1, steps = 20) {
  const cdp = await page.context().newCDPSession(page);
  await cdp.send("Input.dispatchTouchEvent", { type: "touchStart", touchPoints: [{ x: x0, y: y0 }] });
  for (let i = 1; i <= steps; i += 1) {
    await cdp.send("Input.dispatchTouchEvent", { type: "touchMove", touchPoints: [{ x: x0 + ((x1 - x0) * i) / steps, y: y0 + ((y1 - y0) * i) / steps }] });
    await page.waitForTimeout(16);
  }
  await cdp.send("Input.dispatchTouchEvent", { type: "touchEnd", touchPoints: [] });
}

/** 真实模式：逐屏幕帧记录一个村民的精灵位置和图片，用来判断流畅度（见 K 组）。 */
export function sampleMover(page, id, ms = 5000) {
  return page.evaluate(([id, ms]) => new Promise((done) => {
    const out = [], start = performance.now(); let last = start;
    const frame = () => {
      const now = performance.now(), m = __prehistoricPixiMap.movers.get("u" + id);
      out.push({ t: now - start, dt: now - last, x: m?.sprite.x, y: m?.sprite.y, tex: m?.sprite.texture?.uid, walk: !!m?.walk });
      last = now;
      if (now - start < ms) requestAnimationFrame(frame); else done(out);
    };
    requestAnimationFrame(frame);
  }), [id, ms]);
}
```

**调试模式下点地图**：`tile()` → `S.step(20)` → 再 `tile()` 取坐标 → `page.touchscreen.tap` → `S.step(10)`。

**连点要注意**：双击的判断用真实时间（0.35 秒）。调试模式里两次点击之间要 `page.waitForTimeout`，时间才算数。

### 2.2 调试接口

**`S`：摆局面**

| 调用 | 作用 |
|---|---|
| `S.enter(q)` | 进关卡 q（0–6 战役，7–11 自定义） |
| `S.step(n)` | 走 n 步并画出来 |
| `S.reveal = true` | 每步清迷雾 |
| `S.stock(n, 武器数=9)` | 木、石设为 n，各种武器设为武器数 |
| `S.food(n)`、`S.bones(n)` | 设食物、骨头 |
| `S.look(x, y)` | 镜头对准 |
| `S.building(种类, x, y, 等级)`、`S.buildingNear(种类, x, y, 等级)` | 放一座建好的建筑，返回 id |
| `S.site(种类, x, y)`、`S.siteNear(种类, x, y)` | 放一块工地，返回 id |
| `S.complete(id)`、`S.level(id, 等级)` | 工地立刻完工、改等级 |
| `S.villager(x, y, {age, gender})` | 加我方村民，age < 12 是小孩 |
| `S.enemy(x, y)` | 加敌人 |
| `S.animal(种类, x, y)` | 0 野猪、1 剑齿虎、2 鹿 |
| `S.order(id, x, y)` | 选中他并在那格下命令 |
| `S.giveWeapon(id, 武器号, 仓库id)` | 发武器（他会走去拿） |
| `S.set(id, {AGE, HP, ...})` | 改村民字段 |
| `S.chief(id)`、`S.win()`、`S.lose()` | 指定族长；敌方兵力清零；我方人口清零 |

**注意**：`S.set` 的 `FOOD` 和 `ENERGY` 这两个名字是反的。要改饥饿和疲劳，直接写 `__prehistoricRuntime.denseState[2020 + id]`（饥饿）、`[2121 + id]`（疲劳）。

**`T`：读状态（只读）**

| 调用 | 返回 |
|---|---|
| `T.stock()` | `{people, room, food, wood, stone, bones}`（顶栏的数） |
| `T.villager(id)` | `{id, x, y, inside, age, gender, hp, maxHp, food, energy, mood, type, held, carryKind, carry, targetX, targetY, skills}`，死了是 null |
| `T.villagers()` | 我方活着的村民 |
| `T.building(id)`、`T.buildings(队伍)` | `{id, x, y, kind, site, plannedKind, hp, maxHp, level, work, workers}`；队伍 0 我方，1 敌方 |
| `T.animals()` | `{slot, kind, x, y, hp}` |
| `T.resource(slot)` | `{x, y, kind, amount}` |
| `T.nearest(x, y, [格子值])` | 最近的那种格子，例如树 `-124`、石头 `-125`、浆果 `-63 / -64` |
| `T.freeSpot(x, y, 大小)`、`T.cell(x, y)` | 找空地；读格子值 |
| `T.needsStart()` | 本图从第几步开始饿和累 |
| `T.ui()` | `{screen, onMap, barMode, selected, group, chief, mission, frame, choosingChief, text}` |

**其他可读的值**（`const rt = __prehistoricRuntime, e = rt.denseState, g = rt.game`）

| 值 | 含义 |
|---|---|
| `e[7777 + id] > 0` | 这个人正在跑 |
| `e[1010 + id]` | 他走一格要几步（5–8，跑步减 3） |
| `e[3636 + id]` | 背着的数量（`T.villager(id).carry`） |
| `e[6464 + id]`、`e[2222 + id]` | 职业、帽子 |

| `rt.mainArrays.aShort[0]` | 我方数据：[1] 食物，[2] 木，[3] 石，[4] 骨，[5..10] 武器（棍棒、石头、长矛、石斧、骨锤、战斧），[11] 人口，[16] 居住空间，[17] 族长 id，[18] 配对计时器 |
| `rt.mainArrays.aShort[1][14]` | 敌方兵力 |
| `g.callToArmsActive`、`g.formUpActive` | 全员备战、集结是否开着 |
| `rt.subsystemArrays.bAQ = 2 ** 30` | 让敌人来袭永远不到（要测别的东西时用） |
| `__prehistoricPixiMap.movers` | 地图上每个人的精灵，键是 `u<id>` |
| `__prehistoricScreen.viewTransform()` | 镜头 `{x, y, cssPerGame}` |

### 2.3 每个用例通用的检查

写一个公共函数，每个用例结束都跑：

- 没有页面报错（`pageerror`、控制台 error）。控制台的 `[旧素材]` 警告不算错。
- 所有村民 `hp <= maxHp`；站在地图上的人坐标都在地图内。
- `T.stock()` 没有负数。
- 显示 `.hud-villager` 时 `barMode` 是 1 或 2；显示建筑面板 `.hud-sheet .hud-sheet-row` 时 `barMode` 是 2 或 4。

## 3. 结果怎么报告

每个用例记一行：`ID | 通过/失败/没跑到 | 一句话 | 证据路径`。“没跑到”必须写原因，**不要把没跑到的算成通过**。

失败的用例写一份：

```
编号 / 标题：
类型：规则不符 | 数值不符 | 状态错乱 | 报错 | 画面 | 动作流畅度
严重程度：严重（玩不下去、丢数据）| 中（玩法受影响）| 轻（观感）
复现步骤（最好是一段能直接跑的代码）：
期望（引用本文的用例编号）：
实际（数字、截图、录像路径）：
每次都能复现吗（跑了几次）：
```

**证据**：画面类用例存截图，动作类存逐帧数据（JSON）和录像（`recordVideo`）。

**不确定的不要猜**：写“我观察到 X，不确定算不算问题”。本文标“未核实”的规则，只记录现象，不判失败。

## 4. 已知情况（不要报告成 bug）

- 地图大片全黑是迷雾；灰暗是探索过但现在看不见。
- **第一关建造菜单滑不动**：只有 3 张卡片、1 页。第 2 关起才有多页。
- **全员备战开着时，点一下就跑**（号角按钮发光）。
- 村民快慢不同：走一格 5–8 步，所以快的人走路和慢的人跑步一样快。
- 过了 0.35 秒再点**同一格**也会跑。
- 选中村民点仓库，会打开武器栏。
- 交完货走回去的路上，地图上手里还画着篮子，面板是空袋子。
- 血量低于 2/3 的村民，没选中也带血条。
- 练完的人在训练场门口闲着，不回去采集（目前保留）。
- 全员备战放下后，大家先去仓库拿武器，再到旗子那里站成一团，一直站到点“回去干活”。旗子太近时看着像没动。
- 看到敌方的人，附近的成年人都会过去打，没武器的也去（原版规则）。自定义图上的来袭比战役强，部落被打垮不算 bug。
- 在建筑、工地里的人不在地图上，拖不到、点不到。
- 小屋升级不加人口上限。
- “关于”页是空的；帮助页的文字还没写完。
- 自定义图有的地方很少见到动物。
- 开局 `people: 11, room: 1`，人口超过居住空间是正常的。

### C. 选择和命令的状态转换

| C07 | 选中一个村民 | 点空地 | 他走过去，仍选中，点的格子闪图标约 0.8 秒 |

### K. 画面和动作流畅度 [真实]

**判断方法：不只看截图，要逐帧记录。** 用 `sampleMover` 记位置和图片，同时开录像，失败时抽帧看。

**基线（2026-11-06，Mac，无头 Chrome，390×844，一个人走 5 秒，只量了这一种情况）**

| 量 | 结果 | 说明 |
|---|---|---|
| 逻辑步 | 16 步 / 2 秒 | 约每秒 8 步 |
| 屏幕帧间隔 | 中位 16.6 毫秒，95% 约 30 毫秒，最长 52 毫秒 | 无头软件渲染，不代表手机 |

| 移动中同一张图的最长时间 | 115 毫秒 | |
| 5 秒内不同的图 | 13 张 | |
| 拖地图每屏幕帧位移 | 最大 3.9 游戏像素（手指每 16 毫秒约 5 CSS 像素） | 游戏像素 × `cssPerGame`（基线 1.5）= CSS 像素 |

**判定规则**（阈值是从上面一次测量定的，先在你的环境量一次；不合适就调整，并在报告里写明）

- **跳变**：相邻屏幕帧位移 > 8 游戏像素。
- **平移（滑动）**：位置在变，但同一张图持续 > 400 毫秒。**这是用户最在意的问题。**
- **闪烁**：图片在两个值之间来回切换，或者人物在 `movers` 里消失又出现。

## 6. 一局完整流程（L03 用）

真实模式，像玩家一样操作，全程只用屏幕点击，不用 `S` 改数据，只用 `T` 读。

1. 进 PLOT OF LAND。2 人盖房，3 人采浆果，1 人做饭，其余砍树采石。
2. 依次盖：仓库 → 厨房 → 小屋 ×2 → 军械库 → 健身房 → 靶场 → 小屋 ×2。
3. 军械师造棍棒和长矛。发给 10 个战士（近战、投掷都有），送去训练。
4. 健身房、靶场升到 2 级，继续练到 7。
5. 每 2 分钟记一次：人口 / 成年人、四种资源、闲着的人数、每座建筑从放下到盖好的时间、有武器的人数、练到 7 的人数。

**记录“10 人都有武器”用了多少分钟。** 开发测量（关来袭、木石各给 999）是 18–23 分钟，用户希望接近 15 分钟。只报告数字，不判失败。

## 7. 这套测试替代不了什么

下面这些无头浏览器测不出来，请在报告里写“未覆盖”，不要写通过：

- **真手机上的表现**：软件渲染的帧率不代表手机；手机 GPU 的贴图上限（我们用了 4096 宽的大图）。
- **iPhone Safari**：可以试 `playwright.webkit` 配 `devices["iPhone 13"]`，但它不是真的 iOS Safari；添加到主屏幕的全屏模式也测不了。
- **手感**：拖动跟手、按钮大小是否好按、动画够不够自然，这里只能给数据和截图。
- **声音**。
